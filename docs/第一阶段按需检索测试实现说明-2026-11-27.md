# 长期记忆按需检索｜第一阶段测试实现说明（按冻结稿）

## 临时只读执行器（xin/gateway.py，不接入正式链路）
- 接收结构化检索意图（字段按冻结稿第五节），校验字段类型与白名单（historical_claim / snapshot_conflict / recall_request / insufficient_snapshot）；clarification_needed=true 时不执行。
- 阶梯：一级 当前 ref 精准召回（preferred_ref_ids 只认当前 ref 内的 ID；state_key 取其当前版本 ref）→ 二级 时间区间（模型给的区间，或执行器把模型给的时间说法解析成区间；有关键词时只返回命中关键词的）→ 三级 前后各放宽 1 天（必须有关键词）→ 兜底 本 run 关键词召回（最多 5 条）。
- 终止：某一级找到即停；预算 最多 8 条、1200 字；全部未找到时明确说明检索范围与“范围外无法确认”。
- 只做 SELECT；每次执行前后比对状态表行数，记录是否污染。检索原文只回传本轮，不写库。
- 执行器不补模型没给的条件（例如模型没给关键词就不做三级和兜底）。

## 测试数据（冻结）
- fixtures/stage1_history.json：11-23 猫煤球（三岁）、11-24 降温（无对应状态，不在任何 ref）+ 学做饭、11-25 厨房/房租/菜市场/妈妈要来、11-26 红烧肉焯水；4 条状态及 ref；R 组来源提示的摘要与筛选规则。
- fixtures/stage1_cases.json：Q9（两句，第一句后按 B 层会产生的结果加入“打算搬家”状态，来源为当前消息）、T2、T3、T4、T5、T7；每条写明目标、可接受范围、必须拒绝、证据缺失时行为、是否允许澄清、预期是否触发、目标事件 ID。
- 每次运行从冻结数据新建独立数据库；冻结输入（数据、用例、参数、协议、预算、工具定义、O 组说明）随结果写入 frozen_inputs.json。

## 四组
- S：快照，无来源，不检索；R：快照 + 来源提示（event_id、record_time、topic、abstract、relation）；O：快照（带 key）+ request_history 工具；D：完整原始聊天。
- 四组共用同一 A 层约束；S/R/O 最近聊天 6 条。
- O 组协议：优先工具调用（tools）；不支持时用 `json` 参数改走固定 JSON 兜底。每句最多 2 次检索。

## 自动判定（O 组）
合法触发 / 漏触发 / 误触发 / 正确不触发；非法请求数；目标事件是否命中；预算合规；是否污染。另记录每句输入 token（成本观测）。语义由人工判定（review.md）。

## 已知局限
- 兜底只按关键词，原话里不含关键词的事件找不到（例如“它三岁了”不含“猫”）；这正是本阶段要观测的召回边界之一。
